# i18n / Translation Rules

## 10 Locales (ALL must be updated together)
`en`, `ar`, `es`, `fr`, `ja`, `ko`, `pt`, `ru`, `zh`, `zh_TW`

## When adding a new translation key
1. Add the key to ALL 10 `src/locales/*/messages.json` files
2. English (`en`) is the source — write it first, then translate to all others
3. Each key is a top-level entry in Chrome's `{ "key": { "message": "…", "description": "…" } }` format; no nested keys
4. Run `bun run i18n:check`: it fails when any locale is missing a key from `en`, has an extra one, or uses different `{placeholders}` than `en`

## When removing a translation key
- Remove from ALL 10 locale files

## Primitive fragments
- A string used only inside one primitive folder goes in `src/features/plugins/verbs/<name>/messages/<locale>.json` (same format, all 10 locales), not in `src/locales`; it reaches `getTranslationSync` but not `chrome.i18n`. Type its keys by augmenting `PrimitiveMessages` (see `src/utils/translations.ts`).
- `bun run i18n:check` also requires every fragment locale to match its `en.json` and forbids keys that collide with `src/locales` or another fragment.

## Quality
- Translations should be natural, not machine-literal
- Arabic (`ar`) is RTL — ensure UI handles it (see `src/core/utils/rtl.ts`)
