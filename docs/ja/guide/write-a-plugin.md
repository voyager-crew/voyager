# 自分でプラグインを作る

作成モードは、一文をプラグインに変えます。変えたいことを書くと AI がプラグインを書き、インポートする前に Voyager がチェックします。作成モードは Voyager の popup の「マイ作品」カードにあり、できあがるのはローカルプラグインです。

ローカルプラグインは、自分のために作るプラグインです。Gemini、AI Studio、ChatGPT、Claude、DeepSeek、Kimi の見た目やレイアウトを変えられ、保存先は自分のブラウザの中だけ。PR を出す必要も、Voyager のソースコードを手元に用意する必要もありません。

ほかの Voyager プラグインと同じく宣言的で、`plugin.json` マニフェストと CSS だけでできています。プラグイン自身がコードを実行することはありません。Voyager がインポート時に内容をチェックして変更を適用し、オフにすればすべての変更を元に戻します。インポートしたプラグインは最初オフになっているので、中身を確かめてから有効にできます。

## 3 つの作り方

どの方法も最後は「マイ作品」に行き着きます。Gemini と AI Studio では設定カードの 1 つで、動かさなければ「クラウド同期」のすぐ下にあり、popup 上部の「移動先」からも移動できます。ChatGPT、Claude、DeepSeek、Kimi ではプラグイン一覧の下にあります。プラグイン一覧の最後にある「自分で作る」を押すと、カードの最初の入力欄へ移動します。

最初の 2 つの方法は一文から始まります。「何を変えますか？」の欄に書いてください（例：「自分のメッセージの幅を狭くして、サイドバーを隠す」）。その下の「サイト」には、いま開いているタブのサイトが最初から選ばれています。別のサイト向けなら切り替えてください。

### このチャット用にコピー

1. 「このチャット用にコピー」を選び、そのサイトの AI チャットにメッセージを貼り付けます。
2. AI はそのサイト向けの Voyager のページ（例：`https://voyager.nagi.fun/create/claude.md`）を読み、JSON のコードブロック 1 つだけで回答します。AI がリンクを開ける必要があります。
3. 回答を丸ごと「AI の回答を貼り付け」に貼り付け、「回答をチェック」を選びます。
4. そのプラグインで何が変わるのかを、Voyager がわかりやすい言葉で説明します。「インポート」を選んだら、プラグイン一覧でオンにしてください。Gemini と AI Studio では、スイッチはカードのすぐ下に出ます。

Voyager が自分から何かを送ることはありません。メッセージを貼り付けるのも、回答を持ち帰るのもあなた自身です。

### ローカルエージェント用にコピー

コーディングエージェント（Claude Code、Codex、Cursor など）を使っているなら、「ローカルエージェント用にコピー」を選び、そのテキストをエージェントに渡してください。テキストは、Voyager のプラグイン skill に従うようエージェントに頼む内容です。

```text
https://voyager.nagi.fun/skills/write-voyager-plugin/SKILL.md
```

skill には、マニフェストのフィールド、各サイトが宣言している内容、プリミティブ、プラグインにできないことまで、仕様がひととおり入っています。エージェントは `plugin.json` と `style.css` を書き、`npx create-voyager-plugin@latest check` が通るまで実行してから、2 つのファイルを返します。「マイ作品」で「ほかの追加方法」を開き、「ファイルをインポート」を選んで 2 つのファイルを指定します。

skill をいつでも使えるようにしておくなら、エージェントの skills フォルダに `write-voyager-plugin/SKILL.md` として保存します（Claude Code なら `~/.claude/skills/`）。

### 手で書く

Node.js 18 以降が必要です。

```sh
npx create-voyager-plugin@latest init my-plugin --site claude
# my-plugin/plugin.json と my-plugin/style.css を編集
npx create-voyager-plugin@latest check my-plugin
```

`init` は、そのままでチェックを通る `plugin.json` と `style.css` に加えて、そのサイトのルールをまとめた `AGENTS.md` を書き出します。`--site` には `gemini`、`aistudio`、`chatgpt`、`claude`、`deepseek`、`kimi` のいずれかを指定します。

`check` は popup でのインポートと同じチェックをオフラインで実行します。インポートできる状態なら終了コード 0 を返し、そうでなければ問題ごとに `path: message` 形式の行を 1 行ずつ出力します。`--json` を付けると機械可読な形式で出力します。

チェックが通ったら、同じように「ほかの追加方法」の「ファイルをインポート」で 2 つのファイルをインポートします。

## プラグインにできること

- CSS を追加する。適用範囲は、プラグインがページに付ける `gv-` クラスの下に限られます。
- クラスの追加、安全な属性やインラインスタイルの設定、要素の非表示。対象には、サイトが宣言しているセマンティックキー（`userTurn`、`assistantTurn`、`composer` など）か CSS セレクタを指定します。
- popup に設定項目（スイッチ、スライダー、ドロップダウン）を用意する。設定値は `{{key}}` トークンで CSS に渡されます。
- ChatGPT、Claude、DeepSeek、Kimi では、Voyager のプリミティブ（数式コピー、タイムライン、Mermaid 図など）を有効にしたり、Voyager 自身の UI の色を変えたりできます。

## プラグインにできないこと

JavaScript の実行、クリックやキー入力への反応、ネットワークからの読み込み（フォント、画像、スタイルシート）、メッセージ内容の読み取りや書き換え、ほかのサイトでの動作はできません。依頼にそうした要素が含まれている場合、作成用の資料は AI にそのことを正直に伝えさせ、実現できるいちばん近い形で作らせます。

## インポート時にチェックされるルール

共通のマニフェストチェック（[プラグイン貢献ガイド](./plugin-contribution.md)を参照）に加えて、ローカルプラグインは次の条件を満たす必要があります。

- Voyager が対応しているサイトの範囲内の URL にだけマッチすること
- マッチするすべてのサイトが宣言しているセマンティックキーだけを使うこと
- `addClass` 1 つにつきクラスは 1 つだけで、`gv-` で始まること
- 設定は boolean、number、select のいずれかであること（string と color にはまだ popup の UI がありません）
- Gemini と AI Studio では `theme` を使わず、プリミティブは各サイトが許可するものだけを使うこと: Gemini では `formulaCopy`、`vimInput`、`userLatex`、`codeCollapse`、`mermaid`、`wavedrom`、`echarts`, `sendShortcut`, `draftSave`、`turnNavigator`、AI Studio では `formulaCopy`、`sendShortcut`。いずれも Voyager 標準の対応する設定と同じコードを実行する。`formulaCopy` と `vimInput`(数式コピー・入力欄 Vim モード)は、同じページで標準設定とプラグインのどちらか一方だけが動く。ページの読み込み時や、どちらも動いていないときは標準設定が優先され、その後はすでに動いている側がそのまま動き続け、もう一方は一時停止と表示される。どちらかをオフにすると、もう一方が引き継ぐ。`userLatex`、`codeCollapse`、`mermaid`、`wavedrom`、`echarts` は要素ごとに担当を取り合うため、標準設定と同時に動かせる: 相手がすでに処理している行やコードブロックには手を出さない

個人向けGeminiでは、`params.dataBackend: "shared"` と `engine: ">=1.9.0"` を指定すると、ローカルの `turnNavigator` を利用できます。公式タイムラインと同じネイティブのスター・階層データを読み書きし、会話・アカウント・ターンの識別パラメーターは上書きできません。公式の「タイムラインを表示」とは競合するため、先に公式設定をオフにしてからローカルプラグインを有効にしてください。公式に戻すときは、先にローカルプラグインを無効にしてから公式設定をオンにします。Business、Enterprise、独自のサイト範囲には対応していません。

翻訳（`i18n`）は任意です。

## 共有する

ローカルプラグインは自分のブラウザの中にしかありません。別の環境へ移すときは、「マイ作品」の一覧でそのプラグインの「エクスポート」を選び、移した先で JSON ファイルをインポートしてください。みんなの役に立ちそうなら、公式カタログへの収録を提案することもできます。その流れは[プラグイン貢献ガイド](./plugin-contribution.md)で説明しています。

すべてのサイトで、送信ショートカットのプラグインはページごとに1つだけ動作します。送信モードを使用中のプラグインがある場合、もう一方は競合として一時停止します。任意の `mode`（`"engine": ">=1.9.0"` が必要）は `ctrlEnterSends`（既定）または `enterSends` です。IME の確定では送信しません。Gemini と AI Studio でも利用できます。対応モードは以下のとおりです。

Gemini では公式の Ctrl/Cmd+Enter 送信を `sendShortcut` で置き換えられます。公式設定をオフにしてからローカルプラグインを有効にしてください。`ctrlEnterSends` のみ対応し、Enterprise では動作しません。`composerRoot` は通常・編集入力欄を含み、`sendButton` は停止ボタンを除きます。

AI Studio の `sendShortcut` には `params.mode: "enterSends"` が必要です。公式の Enter 送信をオフにするとローカルプラグインに切り替えられます。Ctrl/Cmd+Enter は改行し、Shift/Alt+Enter はホストに任せます。

Gemini の `draftSave` は公式と同じ `gvDraft_<完全な pathname>` を使い、`/u/N` と Gem の経路を保持します。無効にしても保存済みの下書きは残り、同じページの複数プラグインで共有できます。終了前に最後の入力の保存を試みますが、ブラウザー終了時の非同期保存は保証できません。 書き込みと整理の調整は同じページ内に限られます。同じ `/u/N` スロットでメールアドレスを変更しても、保存済みの下書きを共有します。
